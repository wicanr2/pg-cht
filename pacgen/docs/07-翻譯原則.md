# 07 翻譯原則 — pg-cht 系列中文化工程規範

*給接手的譯者、mod 者、review 者。定義「什麼要翻」「怎麼翻」「什麼絕不翻」。*

## 三層原則

### 第一層:**上位原則**(不可撼動)

1. **歷史學界慣用譯 > 電玩雜誌直譯 > 中國大陸簡譯**
   - 台灣 1990-2000 年代軍事史學界的譯法優先
   - 例:「零式戰鬥機」(不用「零戰」)、「B-29 超級空中堡壘」(不用「B-29 超級要塞」)
2. **保留專有型號代碼**
   - F4F / F6F / B-29 / A6M2 / M4A1 / T-34/85 / PzIVG 一律**保留原文**
   - 中文只用於通稱、綽號、艦名
3. **與 PG-cht、AG-cht 一致**
   - 同系列前作已建立的譯名(步兵、騎兵、戰車、驅逐艦...)沿用,不重造

### 第二層:**譯名規範表**(常見類別)

見 [`05-中文化依據.md`](05-中文化依據.md) 完整表格。摘要:

| 類別 | 譯法 | 範例 |
|---|---|---|
| **兵種類別** | 中譯 | Infantry=步兵、Cavalry=騎兵、Engineers=工兵 |
| **飛機型號** | 保留原文 | F4F、A6M、B-29、Zero(綽號保留) |
| **飛機綜合譯** | 通稱時中譯 | 「零式戰鬥機」「野貓式戰鬥機」(全稱) |

### 第三層:**技術限制**(硬約束)

見 [`06-txt-pfp-inplace-patch.md`](06-txt-pfp-inplace-patch.md)。摘要:

1. **byte-length preserving**:任何 patched 檔案(TXT.PFP / PACEQUIP.TXT / EXE)整體 byte 長度不變,避開索引 offset 撞歪
2. **每行 Big5 bytes ≤ 原文 bytes**:超長就用縮字策略(單字/部首/常見縮寫)
3. **PADDING**:短於原長度用 trailing spaces 補齊
4. **NULL/CRLF 位置守住**:字串結尾的 `\0` / `\r\n` 不能被 Big5 高位 byte 蓋掉
5. **不改 lookup key**:`strcmp`/lookup 用的字串表**絕不可原地翻譯**(SCENARIO.TDB 慣例,AG 中文化踩過雷)。要顯示中文就用指標重導向另存中文副本

## 譯名警告章節(考古感,不批判)

以下是本 CHT 專案特意「不採用當年台灣電玩雜誌譯法」的地方,附**考古理由**。詳見 [`05-中文化依據.md`](05-中文化依據.md)。

- Zero **不譯**「零戰」→ 用「零式戰鬥機」(歷史學界規範)
- Wildcat/Hellcat/Corsair **不譯**「野貓/地獄貓/海盜」→ 保留 F4F/F6F/F4U 型號代碼
- Kate/Val/Judy **保留盟軍代號**→ 附註 九七艦攻/九九艦爆/彗星
- Enterprise/Yorktown/Hornet **用歷史譯** → 企業號/約克鎮號/大黃蜂號
- Malaya = 馬來亞(1941-42),**不譯**「馬來西亞」(那是 1963 後的國名)

## 譯名爭議判定 SOP

遇到不確定的名詞:

1. **查歷史學界**:鈕先鍾《第二次世界大戰史》、唐德剛《中日戰爭》、王曾才《西洋現代史》
2. **查中文戰史圈**:《軍事家》雜誌 1990-1998 年、美國海軍研究所中文版《太平洋戰爭》系列
3. **無定論就保留原文**:寧可英文顯示,不做臆造
4. **爭議譯名**:登錄 [`CONTEXT.md`](../CONTEXT.md) 末尾「Flagged ambiguities」等待統一

## 技術實作:兩條路徑

見 [`06-txt-pfp-inplace-patch.md`](06-txt-pfp-inplace-patch.md)。摘要:

### 路徑 A:**byte-length preserving in-place patch**(推薦,v0.2.1+ 採用)

- 適用:PFP 內短字串(單詞、button 標籤)、PACEQUIP.TXT 短單位名
- 工作流:`build_pfp_patches.py`(掃 en/zh 對照產 JSON) → `patch_pfp_v2.py`(套用)
- 優點:不動 IDX、不動檔案結構、fresh source hardlink 測試通過
- 限制:Big5 byte 長度 ≤ 原文;超長需縮字或跳過

### 路徑 B:**檔案獨立翻譯**(v0.1 採用)

- 適用:純文字檔(scenario TIT/DES)、可自由改長度
- 工作流:讀 → 翻 → 存 Big5 → 覆蓋
- 前提:遊戲以 line-based 讀入,無 offset table 依賴
- 驗證:改小樣本測 boot,無 crash 才批次做

## 工程 checklist(每輪 patch 前跑)

- [ ] 譯名符合上位原則(歷史 > 雜誌 > 大陸)?
- [ ] 型號代碼保留原文?
- [ ] Big5 encode 成功 (`.encode('big5', errors='replace')` 無亂碼)?
- [ ] 每行 Big5 bytes ≤ 原文 bytes?
- [ ] 檔案整體 byte length 不變?
- [ ] fresh source hardlink 測試通過 boot?
- [ ] 打包後 AppImage 首次啟動能到主選單?

## Glossary 檔案結構

pacgen 專案下的 glossary 檔家族:

- [`glossary.tsv`](../translations/glossary.tsv) — 主 glossary,238 條(兵種/地形/國別/月份/action/menu 等)
- [`glossary_short.tsv`](../translations/glossary_short.tsv) — 縮字別名,22 條(超原長度時用短版覆蓋)
- [`glossary_equip.tsv`](../translations/glossary_equip.tsv) — PACEQUIP.TXT 專用,34 條(裝備名/艦名/日文兵種)

**優先順序**(高 → 低):`glossary_short` > `glossary_equip` > `glossary`

同一 key 出現在多份 tsv 時,短版/專用版覆蓋通用版。實作見 `apply_glossary.py` 的 dict merge 邏輯。

## 已知限制(v0.6 狀態)

1. **遊戲用自訂 bitmap 字型** `TFONT1.DAT`,wine 的 font substitution **無效**於這條 render 路徑
   - GDI 繪的文字(EditControl / MessageBox / dialog title)→ wine 字型代換有效 → Big5 顯示正常
   - 遊戲自繪的文字(main menu button / status bar / 戰場數值)→ bitmap 字型無 CJK glyph → **顯示 Big5 為亂碼**(Latin-1 accented chars)
2. **v0.1 CHT TIT/DES 顯示正常**是因為那些走 GDI 路徑,不是 bitmap font
3. **v0.4+ PFP UI patch + v0.6 PACEQUIP** 大部分走 bitmap font,**目前顯示為亂碼**
4. **正解**是替換 TFONT1.DAT 為含 Big5 glyph 版本,或 patch EXE 讓它走 GDI TextOut,兩者皆重工程
